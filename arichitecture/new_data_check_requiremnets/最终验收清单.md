# 一、总的工程改造原则

这次改造不能再按“数值列统一清洗”的思路做，而必须按 domain 和字段语义治理。每个字段都要进入字段注册表，至少明确六件事：

第一，字段类型。\
区分为原始价格量字段、分位成本字段、比值字段、位置字段、收益率字段、排序字段、评分字段、状态字段。

第二，理论定义域。\
例如 \[0,1]、\[-1,1]、(0,+∞)、全实数、非负金额。

第三，缺失语义。\
要明确是“源数据缺失”“业务不适用”“分母为 0 无定义”“质量不合格主动置空”。

第四，零值语义。\
要明确 0 是“真实 0”“停牌/无交易”“聚合失败默认 0”“缺失填充成 0”。

第五，异常处理方式。\
不是所有字段都能用 3sigma，更不能全部走同一个 winsorize。\
收益率类一般不用硬截尾；\
比例类优先做超界检查；\
估值类优先做 log / rank 映射；\
不平衡度类优先做分母与低流动性质量控制。

第六，是否需要伴随标签。\
例如 `is_missing`、`is_zero_denominator`、`is_low_liquidity`、`is_clipped`、`is_out_of_domain`、`is_single_trade_window`。\
以后下游建模不再只吃“一个值”，而要吃“值 + 状态”。

# 七、最终验收清单

最终验收不能只看“图看起来顺了”，必须形成工程化、自动化、可回归的验收框架。我建议分成七层。

## 验收层 1：字段定义验收

每个字段必须有文档项：

- 字段含义
- 公式
- 理论范围
- 是否允许 0
- 缺失语义
- 是否需要标签
- 下游推荐输入版本\
  没有这些定义的字段，不允许进正式产线。

## 验收层 2：原始合法性验收

检查所有 domain 的根字段：

- 价格是否正值
- 区间关系是否成立
- 成本分位是否单调
- 买卖金额是否非负
- 份额/比率是否超界
- 分母是否为 0

## 验收层 3：缺失与零值验收

针对每个字段同时监控：

- Null%
- Zero%
- `zero_but_should_not` 比例
- `missing_but_filled` 比例\
  尤其监控：
- `hour1_ret`
- `imb_elg_amt`
- `dv_ttm`
- `winner_rate_pct`
- `circ_mv_to_total_mv`

## 验收层 4：边界堆积验收

对每个连续字段检查：

- `Min == Q01` 是否异常频繁
- `Max == Q99` 是否异常频繁
- 在固定边界处的堆积占比\
  重构后，只有理论边界字段才允许较强边界堆积；收益率、位置类、效率类不应再出现大面积人工断崖。

## 验收层 5：状态位覆盖验收

所有关键衍生字段必须有对应质量标签。\
至少包括：

- `is_missing`
- `is_den_zero`
- `is_low_liquidity`
- `is_out_of_domain`
- `is_single_trade_window`
- `is_extreme_but_valid`\
  验收标准是：没有状态位支撑的复杂比值字段，不通过。

## 验收层 6：抽样回放验收

每个 domain 随机抽取极值、零值、缺失值样本各 100 条，回看原始输入，人工确认：

- 该值是否可解释
- 是否由公式正确产生
- 是否由 fallback 伪造\
  这一步非常重要，因为很多问题只靠统计看不出来，比如 `vwap_close_bias_1h` 这种公式方向错位。

## 验收层 7：建模与研究验收

最终不仅要数据“干净”，还要证明“信息没有被洗没”。\
建议对比：

- 重构前后单变量 IC
- top/bottom 分组收益差
- 缺失分桶表现
- 原值 vs robust 值效果
- 加入状态位后模型提升\
  特别关注四类指标：
- `ret_cc_1d` 去截尾后是否提升极端行情识别
- `hour1_ret` 修复后是否恢复分层能力
- `imb_elg_amt` 去伪零后是否更能区分流动性枯竭与中性
- 筹码位置类去边界压平后是否恢复尾部区分度

你后续真要把这件事做成工程，我建议最终交付不要只是改代码，而是交付下面五份东西：

第一份，字段注册表。\
