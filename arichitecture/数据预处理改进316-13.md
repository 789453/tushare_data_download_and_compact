## 2. `dist_upper_shadow_ratio`

### 现在看，这张图其实大概率“逻辑没错，视觉上容易被误判”

`upper_shadow_ratio_raw` 现在：

- Null 0.54%
- Zero 12.07%
- Min 0
- Max 1
- Q01 也是 0
- Q99 是 0.8333

这说明它是一个非常典型的**有界比例变量**。\
上影线比例天然就在 \[0,1]，0 和 1 都是理论合法边界。\
所以如果你的图看起来像“左边界有堆积、右边界碰到 1”，这本身**不构成异常证据**。

### 真正值得检查的地方

这张图真正的问题不是“被截尾”，而是**你现在是否把本来不该算的日 K 也算进去了**。

因为上影线比例通常类似：\
`(high - max(open, close)) / (high - low)`\
那么当：

- `high == low`
- `open/high/low/close` 中存在无效值
- 当日一字板、停牌占位、异常 OHLC\
  时，这个比例要么应为 NaN，要么要走专门规则，不该直接输出 0 或 1。

而你现在有个信号很关键：\
`ohlc_invalid_flag` 是一列全 0 的 flag，也就是**它没有拦住任何样本**。\
这很不正常。因为在这么大的全市场历史数据里，几乎不可能没有任何一条 OHLC 结构异常记录。

### 所以这张图的真正问题是

不是 upper shadow 自己的范围不对，而是：

- **OHLC 异常检测过于宽松或者没真正生效**；
- **高低价相等 / 极窄振幅样本是否被安全处理**，你现在从统计表里还看不出来；
- 如果这些样本没过滤，它们会把 0 和 1 两端堆得更明显。

### 针对这张图的精准修改

1. **补一个真实可用的 K 线可计算性判定**\
   需要有单独条件：
   - `high >= max(open, close)`
   - `low <= min(open, close)`
   - `high > low`
   - `open, high, low, close > 0`\
     不满足时，`upper_shadow_ratio_raw = NaN`，而不是 0。
2. **新增** **`range_too_small_flag`**\
   即使 `high > low`，但若 `high - low` 小到数值不稳定，也建议不算。\
   这一步对上下影线比例都重要。
3. **不要对它做任何 winsorize**\
   因为上影线比例天然就在 \[0,1]。\
   如果你因为图不好看再做截尾，那是在破坏定义。
4. **绘图时单独区分“合法 K 线样本”和“全部样本”**\
   如果过滤掉 `range_too_small_flag` 后图正常，那问题就不是字段，而是样本池。

### 结论

`dist_upper_shadow_ratio` 看起来不顺眼，**更像合法边界变量 + 样本过滤不够严格**，不是截尾错。优先级中等。
