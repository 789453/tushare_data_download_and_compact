下面给出的是一份面向工程落地的重构说明，不写代码，只给出可以直接指导 Python 3.11 数据管道改造的工程文档内容。结论先说：你现在遇到的不是单纯“有异常值，所以做一下 3sigma 就行”的问题，而是**字段语义、分布特征、缺失机制、除零机制、硬截尾策略、以及下游建模接口**被混在一起处理了，最终导致三类严重后果：\
第一，真实极端行情被抹平；\
第二，计算失败和业务中性被错误地统一表示为 0；\
第三，很多字段的统计形态已经不是“市场分布”，而是“清洗规则分布”。这会直接让图的尾部出现暴力截断、边界堆积、零值异常尖峰、分位点和最值重合等问题。你给出的统计结果已经把这些问题暴露得非常明确。总体诊断见总报告 ，重点字段的证据分别来自价格成交量、资金流、分时、筹码、基本面诊断报告 。

一、先明确：为什么不能把所有字段都用统一的 3sigma / clip / fillna(0)

3sigma 的前提是：分布大致单峰、近似对称、尾部由噪声主导、字段量纲稳定。但你的字段明显分成几类，它们的统计机制完全不同：

1. **收益率类**：天然厚尾，且受涨跌停板制度、复牌、除权、极端波动影响，不服从高斯尾。比如 `ret_cc_1d` 的最小值与 1% 分位数完全重合在 -0.0953，最大值与 99% 分位数完全重合在 0.1000，这不是市场天然分布，而是已经被人为截在接近 ±10% 附近了 。如果市场里存在 20cm 标的，这样的处理会把制度上有意义的极端收益直接砍掉。
2. **比例/份额类**：如 `large_buy_share`、`volume_concentration_pm`、`price_pos_hist`，理论定义就天然在 \[0,1] 范围内，这类字段不需要再做基于 sigma 的截尾，而要检查**是否存在超界、是否存在边界堆积、是否由分母异常导致集中到 0/1**。例如 `volume_concentration_pm` 的统计范围本身就在 \[0,1]，但这里真正值得怀疑的不是它落在 \[0,1]，而是它是否在低成交样本上被“数学上合法但业务上失真”地计算了 。
3. **不平衡度/净流入归一化类**：如 `imb_*`、`net_mf_to_amount`、`flow_divergence`，它们常见定义本来就在 \[-1,1] 或相对狭窄范围，但问题是：**边界值 -1/1 是极端真实行为，还是由分母为 0、单边为 0、缺失被填 0 后制造出来的伪边界？** 你这里 `imb_elg_amt` 零值比例高达 27.84%，且最值与分位数都钉在 -1/1 。这非常像“分母接近 0 / 一边缺失 / 填 0 后运算”与“硬 clip”共同作用后的产物。
4. **价格位置和筹码结构类**：如 `close_vs_cost50`、`close_vs_weight_avg`、`chip_width_95_5`。这些字段不是简单噪声，而是结构状态量，尾部本身就是信号。`close_vs_cost50` 的最小值和 1% 分位数都在 -0.25，最大值和 99% 分位数都在 0.6676，明显存在强边界或者先验裁切 。如果这个边界不是定义推导出来的，而是人为 clip，就会扭曲筹码松紧和套牢盘状态。
5. **基本面估值类**：如 `pe_ttm`、`ps_ttm`、`pb`。这些字段本来就极端偏态，甚至跨数量级。比如 `ps_ttm` 平均值 37694，但 99 分位数仅 57.6979，最大值高达 6,318,763,008，这说明分布高度右偏，且极端值多半来自分母极小、异常财报时点或数据质量问题 。这类字段不能简单用统一 clip，需要先区分“经济含义异常”和“计算分母失真”。

所以，这次重构不应该问“到底是 3sigma 还是 5sigma”，而应该问：**每个字段属于哪种统计家族，它的异常、缺失、零值、边界分别代表什么。**

二、从你现有结果反推：目前最严重的不是噪声，而是处理逻辑污染了分布

1. **价格成交量域：收益率字段被制度性截平**

`ret_cc_1d` 范围为 \[-0.0953, 0.1000]，且 1% 分位数等于最小值，99% 分位数等于最大值 。这说明至少有两种可能：\
要么你直接按分位数 winsorize 到 1%/99%；\
要么你又叠加了制度上接近 10% 的硬截尾。\
无论哪种，都有工程问题。

问题不在于“10% 不是常见涨跌幅吗”，而在于它**把市场制度差异消掉了**。A 股现在不同板块有不同涨跌幅限制，特殊状态还有 ST、停牌复牌等情形。统一把 `ret_cc_1d` 压到接近 ±10%，等于让模型失去识别板块制度、事件驱动、极端冲击的能力。\
`ret_oc_1d` 被截到 \[-0.5, 0.5]，这比日收盘收益范围宽很多，但仍像人为上限，而不是数据自然分布 。如果你画图时出现“尾部平切”，这里就是首要原因。

1. **分时域：`hour1_ret`** **的 85.03% 零值不是正常市场现象**

`hour1_ret` 零值比例 85.03%，同时 Q01/Q99 仅约在 -0.0056 / 0.0065 附近，均值几乎 0 。这已经不是“第一小时收益率通常不大”的问题，而更像**取了同一个价格作为开和收**、或者**无交易时被默认相等**、或者**聚合粒度/时区/截窗错误**。

更关键的旁证是：`hour1_open` 和 `open_day` 的均值几乎一样，`hour1_close` 也几乎等于 `hour1_open` 。这高度可疑。\
一个健康的第一小时收益率分布，不应有 85% 精确等于 0，除非：

- 数据源一小时 K 线本身多数为空；
- 聚合时第一小时窗口只抓到一笔；
- 缺失分钟被前值/开盘价填充；
- `first()` 和 `last()` 实际落在同一条记录。

这类字段不能靠 clip 修，必须回到**窗口定义与聚合逻辑**重构。

1. **资金流域：零值、缺失、边界值混为一谈**

`buy_elg_amount` 零值 36.25%，`sell_elg_amount` 零值 30.02%，`imb_elg_amt` 零值 27.84%，并且 `imb_elg_amt` 的范围和极端分位都正好顶到 \[-1,1] 。\
对超大单流入这类字段而言，真正的业务情况至少有四种：

- 真实没有超大单成交；
- 该日整体停牌/近乎无量；
- 数据缺失或源表未覆盖；
- 分母为 0，公式无法定义。

但如果你用 `fillna(0)`，这四种情况就都被压成“中性”或“无流入”，随后再参与比值计算时，0 还会进一步制造假边界。\
例如不平衡度通常定义为 `(buy - sell) / (buy + sell)`。\
当 buy=sell=0 时，这个值不是 0，而是**未定义**。你若填 0，相当于告诉模型：这一天有明确定义的“完全平衡资金行为”。这在统计上是错的，在业务上也错。

`net_mf_to_amount` 的范围为 \[-0.4432, 0.3240]，最小值与 1% 分位重合，最大值与 99% 分位重合 ，同样说明尾部被处理过。净流入相对成交额的比值，本来就属于事件型厚尾，不宜暴力分位剪切。

1. **筹码域：边界效应说明有先验裁剪或保护性 clip**

`close_vs_cost50`、`close_vs_weight_avg`、`chip_width_95_5` 都表现出分位点与边界贴合，特别是 `close_vs_cost50` 在 -0.25 和 0.6676 处有明显边界感 。\
如果这个字段定义是 `(close - cost50) / cost50`，那它理论上并没有这样一个天然固定上界，更不该在 99 分位与最大值完全一致，除非你提前做了裁剪。\
筹码结构类因其本身就是“位置关系”指标，尾部往往对应强趋势、深度套牢、筹码空档等状态，是高价值信号，过度 clip 会显著削弱区分度。

1. **基本面域：问题不是要不要截，而是先判断是否该转型**

`pe_ttm` 最大值 2,653,832，`ps_ttm` 最大值更夸张；而 `dv_ttm` 缺失率 34.98%，`valuation_compress_score` 全为负区间 \[-0.9998, -0.0004] 。\
这里的核心不是简单地“去极值”，而是：

- 估值类应该先做**正负可定义性检查**；
- 高度偏态字段应该转为 log / signed-log / 分位秩，不是直接在原尺度截；
- 缺失较高的股息率、EBITDA 类要分析缺失机制，是行业结构性缺失，还是源表覆盖不足。

***

三、建议的重构总原则：从“统一清洗函数”改成“字段家族治理”

建议不要再有一个通用 `winsorize_series` 对所有数值列一把梭。工程上要引入“字段注册表”，每个字段至少配置以下属性：

- 字段家族：return / ratio / bounded\_ratio / amount / valuation / rank / structure / count
- 理论定义域：例如 \[0,1]、\[-1,1]、(0,+inf)、实数
- 缺失语义：unknown、not\_applicable、no\_trade、truly\_zero
- 是否允许 0：allowed / conditionally\_allowed / suspicious\_zero
- 是否允许负值
- 推荐变换：none / log1p / signed\_log1p / rank\_gauss / asinh
- 推荐异常处理：none / business\_cap / robust\_quantile / MAD / stateful\_rule
- 是否需要伴生指示器：is\_missing、is\_zero\_denominator、is\_suspended、is\_low\_liquidity、is\_clipped

这个注册表是这次工程重构的核心。后面所有处理都由“字段语义”驱动，而不是由“数据类型是 float，所以 clip 一下”驱动。

四、针对各字段族给出明确、可落地的处理方案

1. 价格收益类：`ret_cc_1d`、`ret_oc_1d`、`gap_open`、`hour1_ret`、`lasthour_ret`

处理原则：\
收益率不是普通异常值问题，而是**制度上有边界、事件上有跳变、统计上厚尾**的问题。

建议逻辑：\
第一，不做统一 1%/99% winsorize。\
第二，先做**业务合法性校验**，再做温和稳健化。\
第三，收益率类保留原始列，再额外派生稳健版本，不能覆盖原值。

具体建议：

- 对日频收益率，合法性检查应结合市场板块、ST 状态、复权方式、前收是否有效。
- 将“超出理论制度极限很多”的记录标记为疑似源数据异常，而不是直接裁掉。
- 常规样本下可以用更宽的极端分位，如 0.1%/99.9%，或者用滚动 MAD 做软裁切，而非固定 3sigma。
- 建议新增字段：`ret_cc_1d_raw`、`ret_cc_1d_robust`、`ret_cc_1d_is_extreme`。
- 对 `ret_oc_1d`，\[-0.5, 0.5] 明显像保护性边界，建议取消硬裁剪，改为异常标记。
- 对 `gap_open`，其范围目前非常窄且边界感明显 ，若由预开盘机制决定，可以保留，但要验证是否也被分位裁剪过。

对 `hour1_ret` 的专项重构：

- 绝不能把无交易窗口算成 0 收益。
- 第一小时定义必须显式固定：例如 09:30:00–10:29:59。
- `hour1_open` 应取该窗口首笔成交价；`hour1_close` 取末笔成交价；若窗口内无成交，则整列置 NaN，并加 `hour1_has_trade=0`。
- 若只有一笔成交，可保留收益为 0，但要加 `hour1_trade_count=1` 或 `hour1_single_print=1`，避免与真正平稳行情混淆。
- 对停牌、临停、极低流动性股票，建议独立标签，不与 0 收益混为一类。

这一步做完后，`hour1_ret` 的 85% 零值应显著下降；若仍高，说明源数据粒度或时间对齐还有问题。该问题的严重程度从现有统计看非常高，是必须优先返工的模块 。

1. 资金流比值类：`imb_sm_amt`、`imb_md_amt`、`imb_lg_amt`、`imb_elg_amt`、`net_mf_to_amount`、`flow_divergence`

处理原则：\
分母为 0 时，不定义；低成交时，不可信；边界值有业务意义，不应随意 clip。

建议逻辑：

- 统一将 `(a-b)/(a+b)` 这一类公式拆成三层：\
  1）原始买卖额；\
  2）分母质量标签 `den = a+b`；\
  3）结果值与状态位分开存。
- 当 `den == 0`，结果设 NaN，新增 `den_zero_flag=1`。
- 当 `0 < den < liquidity_threshold`，结果可算，但新增 `low_confidence_flag=1`。
- 当 buy 或 sell 缺失时，不得先填 0 再计算，应先标注 `source_missing_flag=1`。
- 边界 -1/1 保留，因为它可能代表单边极端流入流出，但同时记录是否由极低分母触发。

针对 `imb_elg_amt`：\
现在 27.84% 零值太高，说明 0 被当成缺失兜底了 。重构后建议至少拆成：

- `imb_elg_amt_raw`
- `imb_elg_amt_valid`（仅在分母足够时定义）
- `imb_elg_amt_den_zero_flag`
- `imb_elg_amt_low_liq_flag`\
  这样模型才能学到“超大单缺失/无交易”和“超大单真正平衡”不是一回事。

针对 `net_mf_to_amount`：

- 当 `amount` 很小的时候，该比值会天然放大，极端值未必是错，但可信度下降。
- 不建议直接 clip 到固定上下限。
- 建议使用分层处理：高流动性样本保留原值，低流动性样本仅作为低置信度特征使用，或单独训练时加权。
- 可以对原始净流入额用 signed-log 变换后再做相对值比较，而不是强行在比值空间裁切。

1. 比例与份额类：`large_buy_share`、`large_sell_share`、`volume_concentration_pm`、`price_pos_hist`

处理原则：\
这类字段本身有理论边界，重点不是截尾，而是校验分母与边界堆积。

建议逻辑：

- 对理论区间 \[0,1] 的字段，只做超界检查，不做 sigma 裁切。
- 若出现大量 0 或 1，要区分：真实边界、分母过小、分子缺失被补零、整数截断。
- `volume_concentration_pm` 若定义为下午成交量 / 全天成交量，那么在全天量为 0 时应为 NaN，不是 0。现在它最小值为 0，最大值为 1，分布看似正常，但仍需用低成交过滤验证 。
- `price_pos_hist` 在 \[0,1] 边界上集中可能是真实现象，也可能来自历史高低价相等或极窄区间。需引入 `hist_range = his_high - his_low` 作为质量因子。

1. 筹码结构类：`close_vs_cost50`、`close_vs_weight_avg`、`chip_width_95_5`、`chip_width_85_15`、`overhang_95`、`support_5`

处理原则：\
尾部是信号，不是垃圾。先校验定义，再决定是否稳健化。

建议逻辑：

- 这类字段不要用统一分位截尾。
- 先校验底层筹码分位成本是否单调：`cost_5pct <= cost_15pct <= cost_50pct <= cost_85pct <= cost_95pct`。
- 如果成本分位本身存在逆序或 0 值异常，再往上算出的结构字段都会失真。
- 对 `close_vs_cost50` 和 `close_vs_weight_avg`，如果公式分母是成本价，则当成本价缺失或接近 0，结果应为 NaN 并标注。
- `chip_width_95_5`、`chip_width_85_15` 体现分布宽度，不建议裁切，只需对极端宽度做异常审计。

尤其要强调：`close_vs_cost50` 目前的边界行为太强，不像纯市场分布 。如果你想解决图尾部“严重问题”，这类字段的优先级很高，因为它们很可能被人为限制后在图上形成清晰断崖。

1. 基本面与估值类：`pe_ttm`、`pb`、`ps_ttm`、`dv_ttm` 及排名字段

处理原则：\
这类字段不要在原尺度上硬剪；要先做经济意义判定，再转到适合建模的空间。

建议逻辑：

- `pe_ttm`、`ps_ttm`：优先保留原值，但下游建模使用 log 或分位 rank 版本。
- 负值、极大值、分母极小值需要状态标记。
- `dv_ttm` 缺失率 34.98% 很高 ，不能简单中位数填充，因为“无分红”和“未知分红”不是一个概念。建议拆成 `dv_ttm_value` + `dv_ttm_missing_flag` + `dv_ttm_zero_flag`。
- 排名字段如 `*_rank_ind`、`*_rank_mkt` 本身已经是稳健映射，不应再进一步 winsorize。
- `valuation_compress_score` 全为负区间，需复核公式是否本来就如此定义，若是，那它更像方向性评分，不应再做对称化。

五、关于“缺失、范围、异常、0”的统一治理框架

这是最关键的一段。你要求“在缺失、范围、异常 0 的问题上都解决”，正确做法不是四类问题各写一个 if，而是建立统一语义层。

1. 缺失不是一种状态，至少分四类：

- 源数据缺失：上游没给；
- 业务不适用：如停牌、无分红、无超大单交易；
- 计算无定义：如分母为 0；
- 清洗后置空：识别为坏值后主动置 NaN。

工程上必须拆开，不允许全部落成 NaN 后再 `fillna(0)`。

1. 0 不是一种状态，至少分三类：

- 真实为 0；
- 低精度近似 0；
- 缺失兜底成 0。

比如 `hour1_ret=0`、`imb_elg_amt=0`、`buy_elg_amount=0`，这三种 0 的业务含义完全不同。\
解决方法不是“别填 0”，而是**同时保留值和状态位**。

1. 范围问题分三层：

- 理论超界：一定错；
- 制度边界：可能对；
- 统计极端：不一定错。

只有第一层应该强处理；第二层要结合业务制度；第三层最多软稳健化。

1. 异常值分两类：

- 数据异常：错值、乱值、时间错位；
- 业务异常：涨停、爆量、极端净流入。

绝不能用同一套 clip 同时处理。

六、建议的工程重构流程

第一阶段：字段治理注册\
把每个字段登记到字段字典里，明确家族、理论范围、分母来源、缺失语义、允许的变换方式。

第二阶段：原始层与特征层分离\
Raw 层只做格式化、主键去重、基础合法性校验，不做重清洗。\
Domain/Feature 层才做业务衍生。\
任何稳健化列都以新字段形式产生，不覆盖原字段。

第三阶段：计算前质量检查\
凡是分式、比例、位置类字段，先检查分母、窗口、排序、时间对齐。\
不满足条件先打标，不直接计算。

第四阶段：稳健化后处理\
只对明确需要稳健化的字段派生 `_robust` 列。\
收益率、净流入类采用宽分位/MAD；\

七、你这个案例里最优先要返工的模块顺序

第一优先级：`hour1_ret` 与相关分时窗口逻辑。因为 85.03% 精确零值已经远超正常范围，极可能是计算逻辑错，不是清洗策略问题 。

第三优先级：`ret_cc_1d`、`ret_oc_1d` 的截尾规则。因为这会系统性抹掉高价值极端收益信号 。

第五优先级：估值/基本面字段的高缺失与偏态建模接口。因为这更多是建模映射问题，不一定是原始错误，但需要体系化治理 。

八、重构后的验收标准，不是“图变好看”，而是“分布重新有业务解释”

你提到“找了几个图，他们的结尾有严重问题”。工程上不能以图形顺眼为验收目标，而要以以下标准验收：

1. 尾部不再出现明显人工断崖，除非该字段本身有理论/制度边界。
2. 最值与 Q01/Q99 大面积重合的情况显著减少。
3. 关键字段零值比例回落到可解释水平。尤其 `hour1_ret` 和 `imb_elg_amt`。
4. 缺失率变化可解释：若缺失上升，是因为把原来错误的 0/边界伪值还原成未定义。
5. 下游模型离线评估中，带状态位的版本优于简单填 0 版本。
6. 极端样本抽查时，能说清楚每个极值来自真实市场还是计算失真。

真正专业的数据工程不是把尾巴磨平，而是让每一个尾部、零值、缺失、边界都“有出处”。

九、最后给出一句最明确的判断

这批结果说明，你当前的问题核心不是“3sigma 范围是不是太大”，而是**你把不同语义的字段，用相同的清洗动作处理了**。\
对收益率类，问题是过度截尾；\
对资金流类，问题是缺失与 0 混淆、分母无定义被伪装为中性；\
对分时类，问题更像窗口聚合或交易稀疏情况下的错误定义；\
对筹码类，问题是结构尾部被裁掉；\
对基本面类，问题是应该先做经济语义映射，再做稳健化。

因此，这次重构的正确方向不是“把 3sigma 改成 5sigma”，而是：\
**按字段语义分家族治理，原始值与稳健值并存，计算值与状态位并存，坏值识别与业务极值严格分离。**\
